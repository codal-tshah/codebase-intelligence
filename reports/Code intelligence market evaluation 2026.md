# Codebase Intelligence delivers locally, but trust is its gap

## Executive summary

Codebase Intelligence mostly solves the problems it set out to solve, but it has not yet shown that its answers can be trusted. The 2026-11-23 capability audit mapped each README promise to code and tests. It found parsing (Python AST and tree-sitter TypeScript/JavaScript), cross-stack HTTP linking, the view catalog, incremental indexing, CLI, MCP, impact analysis and grounded chat all **implemented**. Next.js detection, monorepos, some job schedulers and editor packaging are **partial**, and a packaged GitHub Action is **missing** ([capability audit](../research_notes/Code%20intelligence%20market%20evaluation%202026/product-capability-map.md)). The market has moved from human-only visual maps toward agent-first MCP servers where the graph supplies LLM context ([GitNexus](https://www.everydev.ai/tools/gitnexus), [Greptile](https://www.greptile.com/docs/code-review/key-features)). The product's local-first SQLite design, static UI-to-handler-to-model tracing and combined dashboard, CLI and MCP surface fit that shift. Its main exposure is the lack of a visible confidence model: leading static indexers label every edge as resolved, inferred or ambiguous and report unresolvable dynamic calls instead of guessing ([StrataGraph](https://stratagraph.dev/docs/accuracy/methodology), [OpenLore](https://github.com/clay-good/OpenLore/blob/main/docs/cross-service-topology.md)). The second exposure is that `build_context` is symbol-shaped and snippet-count-limited, while the market standard is task-shaped, token-budgeted and flags missing evidence ([RagCode](https://github.com/MarshallEriksen-Neura/ragcode)). On technology, the evidence supports **retaining** tree-sitter, partially **adopting** ast-grep, PyCG and SCIP, **adopting** Semgrep only for specific semantic work, and **deferring** Joern. The leading rival, GitNexus, is licensed noncommercial, which leaves room for a permissively usable local tool ([GitNexus](https://github.com/abhigyanpatwari/GitNexus/)). This report is analysis only. The P0 to P3 recommendations below are not committed fixes.

## The market has split into four camps, and agent-first is winning

Code intelligence tools now fall into four groups: search and navigation (Sourcegraph, CodeQL), visual mapping and tracing (CodeSee, Understand Anything), review and agent acceleration (Greptile, GitNexus, CIS), and local RAG or wiki (DeepWiki) ([competitive landscape notes](../research_notes/Code%20intelligence%20market%20evaluation%202026/competitive-landscape.md)). The decisive shift is that MCP is now the delivery channel. GitNexus ships 17 MCP tools including `impact`, `trace` and `api_impact` ([source](https://www.everydev.ai/tools/gitnexus)). Greptile exposes review-lifecycle tools through MCP ([source](https://www.greptile.com/docs/mcp/overview)). Newer MCP servers bundle 40+ tools by domain (filesystem, symbols, dependencies, git, context packs) ([repo-context-forge](https://github.com/negativexq/repo-context-forge)). Blast-radius analysis is now table stakes rather than a differentiator. Deployment is polarising too: Greptile self-hosting needs Kubernetes, Hatchet and pgvector ([docs](https://www.greptile.com/docs/self-hosting/kubernetes)), while Cartog and ccq ship as single static binaries ([Cartog](https://www.cartog.dev/), [ccq](https://github.com/swchen44/ccq)). Single-binary-plus-SQLite is winning for local development, and a control plane is needed only for team sharing.

## The tech stack is sound; the gaps sit above the parser

The parsing layer is well chosen. Tree-sitter is the industry-standard syntactic layer: initial parses run around 10 ms for 80 KB files and small-edit reparses take about 4 to 16 ms ([benchmarks](https://muhammad-fiaz.github.io/tree-sitter.zig/guide/performance.html)). It is MIT-licensed and actively maintained ([LICENSE](https://github.com/tree-sitter/tree-sitter/blob/master/LICENSE)). It is purely syntactic, so it never resolves types or cross-file references ([ast-grep comparison](https://ast-grep.github.io/advanced/tool-comparison)). That limit explains why the product leans on its own linking layer, which matches the `(METHOD, normalized_path)` join pattern, mount-prefix resolution and dev-proxy handling used by peers ([tieline](https://github.com/nugehs/tieline), [neat](https://github.com/neat-technologies/neat/commit/247b938a9c8f65b82e31ef1fc7758e288a0f259a)). The audit confirms these pieces, including proxy-prefix and nearest-service tie-breaks, are implemented and tested ([capability audit](../research_notes/Code%20intelligence%20market%20evaluation%202026/product-capability-map.md)).

| Technology | Action | Rationale and caveat |
| --- | --- | --- |
| tree-sitter | **Retain** | Foundational, incremental, MIT ([repo](https://github.com/tree-sitter/tree-sitter)) |
| ast-grep | **Adopt (partial)** | Declarative patterns such as `import { $A } from '$B'` replace brittle walkers; MIT, but high maintainer concentration ([comparison](https://ast-grep.github.io/advanced/tool-comparison), [analysis](https://discovergit.app/repo/ast-grep/ast-grep)) |

| PyCG | **Adopt (partial)** | 94.5% precision and 87.8% recall on internal edges ([evaluation](https://github.com/vitsalis/pycg-evaluation)); archived in 2023, restarted in 2026, and not on PyPI ([repo](https://github.com/vitsalis/PyCG)) |
| Semgrep | **Adopt (specific)** | Taint and data-flow engine; the engine is LGPL-2.1 and the rules registry bars bundling into competing products ([licensing](https://docs.semgrep.dev/licensing)) |
| Joern / CPG | **Defer** | About 11 minutes and 30 GB+ heap for the Linux kernel ([changelog](https://github.com/joernio/joern/blob/master/changelog/4.0.0-flatgraph.md)) |

Two licensing points need a decision before any adoption, and the notes do not resolve them. The project's hard rules ban GPL graph libraries, and Semgrep's LGPL engine sits close enough to that line to need an entry in `docs/DECISIONS.md` and a subprocess-only integration. The emerging-project survey also rules out Synaptic (AGPL-3.0, [repo](https://github.com/Synaptic-Graph/Synaptic)) and limits GitNexus to benchmarking because of its noncommercial terms ([repo](https://github.com/abhigyanpatwari/GitNexus/)). Among permissive projects, the useful ideas are CodeGraphContext's pluggable graph backends, codebase-index's ranked read plans with uncertainty reporting ([repo](https://github.com/denfry/codebase-index)), ArchiLens's PR architecture diff ([repo](https://github.com/saurabh-oss/archilens)), and sqry's TOML rule packs ([repo](https://github.com/verivus-oss/sqry)). Telos's semantic-zoom pattern largely overlaps Explore's existing expand, lift and budget levels, so it is **retain-and-observe** rather than adopt.

## Differentiation: one static graph from button click to table

The product's defensible position is the combination, not any single feature. It links UI calls to backend endpoints, handlers and models statically, with no OpenTelemetry instrumentation, and surfaces the result in a dashboard view (API flow), a CLI (`ci trace`, `ci impact --fail-on`) and MCP tools in one local SQLite index. Peers split this across products. Runtime tracers such as Maple, Telemio and Tracepanel connect browser actions to backend traces but need instrumentation ([Maple](https://maple.dev/integrations/), [Telemio](https://telemio.sh/), [Tracepanel](https://tracepanel.dev/)). Sourcegraph resolves cross-repo symbols with compiler accuracy but does not trace string-based REST calls ([blog](https://sourcegraph.com/blog/cross-repository-code-navigation)). Greptile bridges those gaps with an LLM "detective" that has no deterministic guarantee ([docs](https://www.greptile.com/docs/how-greptile-works/graph-based-codebase-context)). The market notes themselves state that automatic UI-to-endpoint mapping in dynamic SPA frameworks remains unreliable without instrumentation ([competitive landscape](../research_notes/Code%20intelligence%20market%20evaluation%202026/competitive-landscape.md)). Deterministic static linking with bundled endpoint traces in `build_context` is therefore a real edge, and it is the one that most needs a confidence model to back it up. The edge is narrower than it looks. Cross-repo federation is absent, `trace_endpoint` stops at the repo boundary and does not follow queues or external contracts, and the audit counts Explore as missing from CLI and MCP ([capability audit](../research_notes/Code%20intelligence%20market%20evaluation%202026/product-capability-map.md)). One bookkeeping correction: the research notes cite roughly 15 and 20 MCP tools, but `backend/apps/mcp/src/ci_mcp/server.py` registers 21 `@server.tool` decorators, so the code count wins.

## Gaps cluster around epistemic honesty, context shaping and packaging

The largest gap is provenance. StrataGraph's four bands (`RESOLVED` 0.9-1.0, `EXTRACTED` 0.95-1.0, `INFERRED` 0.4-0.8, `AMBIGUOUS` below 0.4) and OpenLore's rule of minting no edge for dynamic targets such as `fetch(endpoint)` exist so downstream agents never treat a guess as a fact ([StrataGraph](https://stratagraph.dev/docs/accuracy/methodology), [OpenLore](https://github.com/clay-good/OpenLore/blob/main/docs/cross-service-topology.md)). The notes record no equivalent in the product. The audit's own FK-resolution figure of about 91% and its module-level-only external-service links ([GAPS FR-3](../docs/GAPS.md#fr-3-status-2026-11-16)) show where unlabelled error can enter agent answers. This is an evidence gap in the notes, not proof of absence, and the first task is to check the code.

The second gap is context shaping. The market's `get_context` accepts a `token_budget` and returns `brief`, `freshness`, `evidence` and `missingEvidence`, with "skeleton" expansion that elides bodies ([RagCode](https://github.com/MarshallEriksen-Neura/ragcode)). The product's `build_context` uses a fixed `max_snippets` and has no missing-evidence signal ([`ci_ai/tools.py`](../backend/packages/ai/src/ci_ai/tools.py)). Impact analysis is BFS blast radius with hop ranking, without ownership or tiered risk, so it falls short of the "High Risk above 5 consumers" style of PR gate ([codeknowledge](https://codeknowledge.dev/docs/MCP-Tools), [`ci_core/insights.py`](../backend/packages/core/src/ci_core/insights.py)). The CLI already exits with code 2 on high risk, but no packaged GitHub Action wraps it ([GAPS P2](../docs/GAPS.md#p2-roadmap)).

The third gap is coverage claims that outrun fixtures. Next.js has no fixture, the TypeScript fixture is React plus Vite, Python and TypeScript monorepo handling has no dedicated regression, Celery beat dictionaries and APScheduler `add_job` calls are undetected, and private-GitHub indexing is unverified against a real repository ([capability audit](../research_notes/Code%20intelligence%20market%20evaluation%202026/product-capability-map.md)). Evidence quality limits this evaluation as well. Star counts and feature claims come from vendor pages and READMEs. Some citations are weak, including the Aider integration (cited to an unrelated repository) and the tRPC pattern (cited to an issue thread), so this report does not rely on them. Scalability of in-memory and embedded graph stores on multi-million-line monorepos is unverified for every tool, including this one ([emerging OSS notes](../research_notes/Code%20intelligence%20market%20evaluation%202026/emerging-oss.md)).

## Conclusion

The evaluation changes the question. The product already matches the market's shape (local, graph-based, MCP-native, with cross-stack tracing most peers lack), so its next failures are more likely to be wrong-but-confident answers than missing features. In an agent-first market the graph feeds an LLM that cannot tell a verified edge from a heuristic one, and honest labelling is cheap compared with the credibility it protects.

The GitNexus license also makes a permissively usable, deterministic tool a strategic niche rather than a me-too product. Defending that niche depends on proof (fixtures for partial claims, labelled edges, token-aware context) more than on adopting new parsers or graph engines. The parsing stack needs only incremental changes: retain tree-sitter, add ast-grep and PyCG selectively, and defer the heavy semantic engines.
